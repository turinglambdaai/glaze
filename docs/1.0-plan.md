# Glaze 1.0 foundation plan

> This plan turns Glaze's proven feature set into a bounded, compatibility-governed platform that another AI can evolve without reconstructing architecture from chat history.

Status: active, 2026-10-15.

## Decision

Glaze is a conditional go for 1.0 stabilization. Product scope is frozen: no new service plugin or packaging format enters the 1.0 line unless it closes a documented HackDigest release blocker. The work now is contract hardening, separation, compatibility, and release evidence.

The 1.0 runtime keeps the proven pure-Racket FFI hosts as the default architecture. A signed prebuilt native shim is not a 1.0 prerequisite. It may be introduced later for a specific measured reason such as an API that cannot be bound safely, a security review finding, or a demonstrated performance/lifecycle limit. This avoids replacing a tested source-level portability model with an ABI and supply-chain problem before evidence requires it.

Packaged applications converge on `#:transport 'native` on Windows, macOS, and Linux. HTTP/SSE remains an explicit development adapter. HackDigest currently uses native transport by default only on macOS; closing that consumer gap is a release gate, not a reason to weaken the framework contract.

## Evidence at the decision point

- The repository is clean on `main` after the 0.15.0 release and the layer-module work.
- The Racket implementation and CLI contain about 17,958 lines. Risk is concentrated in `build.rkt` (1,263 lines), the Windows and macOS WebView backends (1,050 and 977), `native-transport.rkt` (870), `glaze-cli/cli.rkt` (851), and `server.rkt` (692).
- The legacy `glaze` facade exports 464 phase-0 names. `glaze/core` exports 52, while the reviewed layers expose 47 window, 150 service, 103 distribution, and 9 devtools names. Existing tests checked presence but did not reject all accidental additions.
- CI runs the Racket suite on Windows, macOS, and Linux with Racket 9.0 and 9.3; real-window native e2e and package jobs run on all three platforms.
- GLZ1 native transport, streaming, per-window capabilities, typed routes, TypeScript generation, fuzzing, and a resource soak already exist. The old runtime RFC therefore understates implementation progress.
- HackDigest 0.3.1 pins Glaze 0.15.0. Its baseline is green: 41 Racket backend tests and 26 frontend tests plus TypeScript checking. It uses the native transport on macOS and HTTP by default on Windows/Linux.
- `glaze/schema-compat` exists, but products have no committed Glaze schema baseline or `raco glaze schema check` workflow. Compatibility is implemented as a library primitive, not yet operational governance.

## Architecture gates

### G0 — governance is executable

Deliverables:

- one canonical documentation map;
- one current-state architecture owner;
- one API stability policy;
- exact export checks for the stable facade and reviewed layers;
- this active plan, including a single next handoff.

Exit evidence: the new tests fail on an unreviewed export, all local links resolve, and the full Glaze suite passes.

Progress (2026-10-15): complete. Exact export, facade-dependency, and documentation-map checks are active; SVG geometry validation passes; `raco make glaze/main.rkt glaze-cli/cli.rkt` succeeds; and the complete local suite reports 1,279 passing tests.

### G1 — application schemas are release contracts

Add `raco glaze schema write` and `raco glaze schema check --json`. A project declares the module and exported route-list binding to inspect. The baseline format is versioned, deterministic, diffable JSON and contains GLZ1 version, commands, named types, errors, and compatibility-significant ordering.

Compatibility rules must cover command removal/rename, parameter names/order/types/requiredness, result types, error-code removal, record fields/order/types, enum cases/order, and protocol version. The build and `inspect`/`doctor` paths report a missing baseline, but development remains possible before one is committed.

Exit evidence: a generated sample and HackDigest commit baselines; compatible additions pass; every breaking fixture fails with machine-readable reasons; both CI workflows run the focused check.

Progress (2026-10-15): the framework vertical slice is implemented. The CLI
writes and checks deterministic version-1 JSON derived from the same
`build-hello` GLZ1/Keel projection used at runtime. Compatibility fixtures cover
protocol/schema metadata, routes, command identity/parameters/results/errors,
records, enums, events, states, requiredness, and ordering. The generated
project includes an import-safe exported `api`, `glaze.rktd`, and a baseline;
inspect, doctor, and build expose baseline readiness; framework CI and the exact
source-package release smoke run the check. HackDigest now commits `glaze.rktd`
and an 11 KB baseline generated from its real `backend/main.rkt`/`api`; the
baseline rechecks without executing its `module+ main` startup path. The
remaining G1 integration slice is to enable HackDigest CI after it pins a Glaze
release containing this command.

### G2 — runtime responsibilities are physically bounded

Split by characterization, not by file size alone:

- `native-transport.rkt`: protocol session/dispatch, stream ownership, resource serving, and generated bootstrap become separate private modules;
- `server.rkt`: HTTP lifecycle, security policy, static resources, and API dispatch become separate private modules using the same bridge dispatcher;
- `glaze-cli/cli.rkt`: command parsing delegates to per-command modules;
- `build.rkt`: build graph, platform staging, signing, and installer formats receive separate owners.

No public import path changes in this gate. Each extraction must reduce the original file, add direct tests for the new private boundary, and preserve native/HTTP golden behavior.

Exit evidence: dependency-direction tests prevent private modules from importing aggregation facades; no runtime/adapter semantic fork exists; all three native e2e jobs and the HTTP adapter suite are green.

Progress (2026-10-15): the low-risk physical foundation is complete. The CLI
dispatcher fell from 851 to 92 lines and delegates to private command modules.
HTTP trust checks moved to a pure security owner; static-resource containment
and native-origin parsing are shared through a resource owner; native browser
bootstrap/client generation has its own pure owner. Generated build entries and
Linux, macOS, and Windows package metadata moved out of the build orchestrator.
The corresponding public owners fell from 870 to 592 lines for native
transport, 692 to 636 for the HTTP adapter, and 1,263 to 879 for build. Direct
tests cover each new boundary, and dependency tests prevent private modules
from importing public or CLI aggregation facades. Public module paths and
runtime behavior remain unchanged. Lifecycle-sensitive native session/stream
ownership plus build staging/signing remain bounded follow-up slices rather
than being mixed into these pure extractions. Current local evidence is 1,330
passing Glaze tests plus successful framework/CLI compilation. HackDigest
remains green with 41 backend tests, 26 frontend tests, TypeScript checking,
the production frontend build, and a compatible real-application schema check.
The G2-N2 slice also moved GLZ1 error envelopes, synthetic requests, route
lookup, typed invoke, capability enforcement, timeout/cancel, and hello routing
into `glaze/private/bridge-dispatch.rkt`. HTTP and native carriers now depend on
that owner directly while `glaze/native-transport.rkt` preserves its public
re-exports; the native aggregate is 365 lines. Direct tests prove reporter
identity, request construction, typed validation, capability behavior,
response pass-through, error redaction, timeout, stream cancellation, hello,
and carrier dependency direction. G2-N3 moved the `native-delivery` value,
full-response framing, stream open/chunk/end framing, UTF-8-safe response
draining, and event framing into `glaze/private/native-delivery.rkt`. The
transport aggregate is now 255 lines and still owns dispatch, event threads,
the active-stream table, and shutdown. Direct tests cover equivalent JS/JSON
carriers, sequenced events, deliberately split multibyte UTF-8, invalid-byte
replacement, writer failure, cancellation, frame order, and stream cleanup.
Local evidence is 1,337 passing Glaze tests plus successful framework/CLI
compilation. HackDigest remains green with 41 backend tests, 26 frontend tests,
TypeScript checking, its production frontend build, and a compatible real-app
schema check. Three-platform native-window e2e remains CI evidence rather than
a local pass.

### G3 — the 1.0 public surface is curated

Classify every reviewed-layer export as stable, expert-level, experimental, or private. Low-level helpers such as Win32 string conversion, allocator internals, backend handles, and package-template implementation functions must not become permanent API merely because an aggregation module once re-exported them.

New applications import `glaze/core` and explicit layers. `glaze` stops growing immediately, gains deprecation guidance, and becomes a compatibility facade. One pre-1.0 release carries shims and warnings before the 1.0 surface freezes.

Exit evidence: exact public snapshots and Scribble coverage agree; HackDigest imports explicit modules without changing behavior; the changelog has a mechanical migration table; a source-package smoke loads every supported public module from an isolated install.

### G4 — platform and release evidence is symmetric

Define one native-host conformance suite for open, resource load, hello, typed invoke, stream, cancel, events, per-window denial, navigation policy, capture, close, and deterministic teardown. Platform-only tests supplement this matrix but cannot replace it.

Release validation must cover tag provenance, exact source-package reinstall, generated project smoke, framework package contents, native application packaging, upgrade identity, and signed-production canaries where credentials are available. Performance budgets are recorded for startup, invoke throughput, stream throughput, idle RSS, long-run handle/thread growth, and packaged size on stable hardware.

Exit evidence: Windows, macOS, and Linux produce equivalent conformance reports; the minimum/current Racket matrix is green; one HackDigest release candidate passes native packaged smoke on every platform.

### G5 — 1.0 go/no-go

Required evidence:

- G0–G4 closed with reproducible commands and linked CI runs;
- no open critical/high security finding at the native resource, message, capability, update, or packaging boundaries;
- API and application-schema baselines frozen for one release candidate cycle;
- migration from the 0.x legacy facade proven in HackDigest;
- documentation, examples, scaffold, inspect/doctor output, and actual runtime behavior agree.

## Workstream ownership

The following streams may run in parallel only when they do not edit the same owner files.

| Stream | Owns | Must not own |
|---|---|---|
| Contract | schema format, compatibility classifier, public API snapshots | platform FFI or installers |
| Kernel | lifecycle, GLZ1 dispatch, streams, resource ownership | CLI UX or consumer code |
| Platform | one OS backend and its conformance evidence | shared protocol semantics |
| Delivery | build graph, signing, update, package verification | application runtime behavior |
| Consumer | HackDigest baseline, bridge, packaged acceptance | framework internals |
| Documentation | canonical owners, migration tables, ADRs | inventing behavior not proved by code/tests |

An agent claims one bounded slice, names the files it owns, records commands and results, and leaves the repository with an updated next handoff. Cross-stream changes require an explicit integration slice after the individual changes are green.

## Risk and rollback

- Public API curation can break unknown 0.x consumers. Roll back by retaining compatibility re-exports for one additional release; never restore accidental growth to `glaze/core`.
- Native-by-default can reveal platform bugs hidden by HTTP. Roll back an affected product to explicit HTTP only as a documented temporary exception while keeping packaged-native as the framework target.
- Physical extraction can alter initialization order or FFI thread ownership. Revert the extraction as one commit; characterization tests and old module paths remain the recovery boundary.
- Schema gates can block a release because the baseline is stale. The repair is an explicit compatibility decision and reviewed baseline update, never an automatic overwrite.
- A prebuilt shim may eventually be necessary. Introduce it behind the existing backend contract and conformance suite so the pure-Racket backend remains a reference and rollback path.
