# Glaze API stability

Glaze is pre-1.0, but public growth is deliberate rather than accidental. The API has four stability tiers.

| Tier | Modules | Rule before 1.0 | Rule after 1.0 |
|---|---|---|---|
| Stable facade | `glaze/core` | Compatible additions only; breaking changes require an announced migration | SemVer compatibility promise |
| Reviewed layers | `glaze/window`, `glaze/services`, `glaze/distribution`, `glaze/devtools` | May be narrowed once during 1.0 curation, with deprecation and migration notes | SemVer compatibility promise |
| Legacy facade | `glaze` | No new exports; existing applications remain supported through the 1.0 migration window | Compatibility shim, then removal only in a major release |
| Unstable | `glaze/experimental` and explicitly documented internals | May change in any release | No stability promise |

`glaze-test/public-api-test.rkt` records every phase-0 variable and syntax export from the stable facade and reviewed layers. A change to those lists is a release decision, not routine test repair. The same commit must:

1. explain the user-visible reason in `CHANGELOG.md`;
2. update the relevant Scribble and Markdown documentation;
3. add a migration note for a rename, move, semantic change, or removal; and
4. pass the full suite on the minimum and current supported Racket versions.

The export snapshot prevents accidental widening, but it does not convert low-level names already exposed by a pre-1.0 aggregation module into good permanent API. The 1.0 curation gate will explicitly classify each reviewed-layer export as stable, relocated to a narrower expert module, or internalized behind `glaze/private`.

Application command schemas form a second compatibility surface. Typed route
names, parameter names/order/types/requiredness, result types, declared error
codes, record fields/order/types, enum cases/order, and the GLZ1 version are
compatibility-significant. Each product declares its import-safe module,
exported route binding, and baseline path in `glaze.rktd`. The checked-in
`glaze-schema.json` is generated by `raco glaze schema write` and enforced by
`raco glaze schema check --json`.

New routes, commands, records, events, states, and trailing optional parameters
or record fields are compatible additions. Removal, rename, type change,
reordering, a newly required field/parameter, removal of a declared error, any
change to an existing closed enum, or a GLZ1/schema-format change is breaking.
The repair for a stale gate is either to restore compatibility or explicitly
review and rewrite the baseline; CI must never update it automatically.

## Reviewed-layer export classification (G3-S2, 2026-10-25)

Every export of the four reviewed layers carries exactly one tier from
the table above. The classification test (`glaze-test/classification-test.rkt`)
parses this section and fails when a reviewed-layer export is added, removed,
duplicated, or left unclassified; `public-api-test.rkt` independently pins the
raw export sets, so the two guards together mean the classification can never
drift from reality in either direction.

Tiers: **stable** keeps the SemVer compatibility promise; **expert-level** is
documented, supported surface that the 1.0 curation may still narrow with a
migration note; **private** names are NOT blessed as permanent API and no
longer appear in the reviewed layers — G3-S2 internalized them behind
`glaze/private` owners (or their raw backend owner modules) and registered
them in the deprecated-shim table below. No reviewed-layer export is
currently experimental; `glaze/experimental` is outside this table by
charter.

### Deprecated private-tier shims (G3-S2, introduced 0.18.0 — removal scheduled 0.19.0)

The 22 private-tier names G3-S1 classified left the reviewed layers in
G3-S2: their canonical homes are the `glaze/private` owners below (or, for
the raw backend accessors and platform-bound default instances, the owner
module that holds the underlying struct or native bindings). The legacy
`glaze` facade keeps re-exporting each name for exactly one release cycle
so 0.x consumers keep loading; import it only through the facade during
that window and migrate before 0.19.0. The classification guard asserts
each name has actually left its former layer and is still reachable
